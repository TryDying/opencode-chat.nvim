# 更新日志

本文件用于记录面向用户的 release-style 项目变更。

当前项目尚未发布版本。

## Unreleased

- 实现基于 `opencode serve` 的 Neovim 原生 Chat UI MVP。
- 支持 `:OpencodeToggle`、`:OpencodeAsk`、`:OpencodeAppendFile`、`:OpencodeAppendSelection`、`:OpencodeNewSession`、`:OpencodeStop`。
- 支持把当前文件或 Visual 选区引用加入下一次 prompt 上下文。
- 默认绑定 Normal `<M-->` 打开/隐藏 Chat UI，Visual `<M-->` 追加选区上下文。
- 增加不读取全局 Neovim 配置的自闭环测试。
- 修复 prompt 接口返回用户消息时，Chat UI 把用户 prompt 当作 assistant 回复渲染的问题。
- 修复 Visual `<M-->` 触发时选区 marks 尚不可用导致无法追加上下文的问题。
- 修复只查询 `/session/:id/message` 导致真实 opencode 无法读取 assistant history、UI 显示空 Error 的问题；现在会兼容 `/project/:projectID/session/:sessionID/message`。
- 重构 MVP：Chat UI 改为消息区 + 输入区，`<C-s>` 提交；测试改用 `/tmp` sandbox；API 优先使用 `/session` 与 `/session/:id/message`；新增 `:OpencodeEdit`，由 opencode backend/agent 执行文件修改。
- 增加可配置 `agent`、`model`、`variant`，测试默认使用 `quick`、`deepseek/deepseek-v4-flash`、`low`。
- 修复新版 `/session` 创建的 session 发送失败后错误 fallback 到旧 `/api/session/:id/prompt` 的问题，并让 HTTP 错误显示 status/body。
- 修复新版 `/session/:id/message` 要求 `model` 为对象而不是字符串导致 HTTP 400 的问题。
- 改进 Chat UI：支持消息区/输入区 `<Tab>` 切换、自动滚动到最新消息、`<C-c>`/`:OpencodeCancel` 取消请求，并阻止请求处理中重复提交。
- 修正 cancel 和配置传递语义：取消改为调用 `POST /session/:id/abort`；`agent/model/variant` 在 session 创建和 message 请求中按不同 schema 发送。
- 修复 abort 后继续复用已取消 session 导致后续请求立即 `MessageAbortedError` 的问题；同时修正 session 使用 `model.id`、message 使用 `model.modelID`。
- 增加 session/model/variant 选择能力：可配置快捷键选择 session、新建 session、重命名 session、选择 provider 分组模型和当前 provider 的 variant；新建 session 不再重启已运行 server。
- 配置改为 provider 分组白名单：`model = "provider/model"`，每个 provider 定义 `variants`，每个 model 定义 `default_variant`，不再支持顶层 `variant`。
- 修复 session picker 直接展示全局 `/session` 导致混入其它 workspace/subagent session 的问题；现在优先使用 project session API，并在 fallback 时按当前 project 过滤。
- 改进 picker/UI 生命周期：选择器优先使用 `nui.nvim`，隐藏 Chat UI 会同步关闭 picker，消息区聚焦不再进入 insert 模式。
- 将主 Chat UI 从 floating window 改为右侧 40% split panel，新增固定底部 status bar；发送请求时显示 Thinking/Streaming 状态，并尝试通过 `/event/subscribe` SSE 增量刷新回复。
- 移除主 UI toolbar/鼠标按钮入口，避免占用 pane 和产生额外窗口标题；全局快捷键改为用户通过 `keymaps` 显式配置，variant 示例改为 `<leader>Xt`，新增 session 重命名入口 `<leader>Xr` / `:OpencodeRenameSession`。
- 修复右侧 panel 各 pane 顶部出现空白 winbar 的问题；`OpencodeToggle` 现在在面板已打开但失焦时会先重新聚焦输入区；新增 `ui.height` / `ui.message_height` 用于调整面板和消息区高度。
- 增加统一上下文追加入口 `:OpencodeAppendContext` / `keymaps.append_context`：Normal 追加当前文件，Visual 追加选区，自动去重并保持代码 pane 焦点；Context 区改为编号展示，支持 `:OpencodeContextRemove`、`:OpencodeContextClear` 以及消息区 `d`/`D` 删除。
- 修复 SSE streaming 事件解析过窄导致回复仍以完整消息一次性出现的问题；现在支持标准 SSE 事件边界、`message.part.delta` 增量事件、`message.part.updated` 全量更新，并按 session 过滤事件。
- 修复 project session API 返回包装结构时 `:OpencodeSessions` 为空的问题；session 列表现在兼容 `data.sessions` / `sessions` / `items` / `list` 和多种 project/path 字段名，并为本进程创建的 session 补齐 project/root 缓存。
- 修复 project session API 返回 200 但空列表时仍直接展示 `(empty)` 的问题；现在会继续 fallback 到全局 session 列表并按当前 project/root 过滤合并。
- 修复 session fallback 仍错误请求 `/session` 导致真实 opencode 下列表为空的问题；现在全局列表 fallback 使用 v2 `GET /api/session`，并保留 `/session` 作为兼容尝试。
- 修复 session 列表可能因从 `/project` 列表猜错当前 project 而为空的问题；现在优先使用 `GET /project/current`，并对 project/session id 做 URL 编码。
- 修复 project session endpoint 或 fallback 返回混合全局 sessions 时未二次过滤的问题；现在所有 session 来源都会按当前 project/root 过滤，支持嵌套 `session.project` 字段。
- 修复 `projectID` 相同但 `directory` 不同的 sessions 被错误放行的问题；现在 session 作用域优先按目录/root 匹配，仅目录缺失时才回退到 project id。
- 改进 session picker 操作：`<leader>Xl` 打开列表后可按 `r` 重命名选中 session，按 `d` 并确认后删除选中 session；新增 `:OpencodeDeleteSession`。
- 增加 Chat pane 自动清理：当前 tab 关闭到只剩 opencode-chat 窗口时，会自动关闭 message/input/status，避免孤立 Chat panel 残留。
- 优化 Chat pane 自动清理：多 tab 场景下当前 tab 只剩 Chat panes 时直接关闭该 tab，不再留下空白 buffer；仅最后一个 tab 时才用普通空窗口保活。
- 修复最后一个 tab 清理 Chat panes 时仍留下空白 buffer 的问题；现在会优先恢复打开 Chat 前的普通代码 buffer，必要时自动重新加载该 buffer。
- 修正最后一个 tab 的 Chat-only 清理行为：用户关闭最后代码窗口时，不再恢复代码 buffer 或留下空白 buffer，而是关闭 Chat panes 后让 Neovim 正常退出。
- 支持 Chat UI tab mirror：不同 tab 可各自打开 Chat panes，但共享同一份消息、输入草稿、上下文、session 和状态；在 Chat 内 toggle 会关闭所有 tab 的 Chat UI。
- 支持 provider ID 含 `-` 的模型配置：除 `["provider-id"] = { ... }` 外，也可使用 `{ id = "provider-id", ... }` 的 array-style provider 条目。
- 配置的 toggle keymap 现在同时注册 Normal/Insert 模式；Insert 模式触发时会先退出 insert，再执行打开/聚焦/隐藏逻辑。
- 改进 project root 识别：焦点在 opencode-chat pane 时会跳过插件 buffer，优先使用当前 tab/已打开 buffer 中的真实文件路径，避免 session 列表按错误 cwd 过滤为空。
- 修复 session picker 展示 subagent/internal sessions 的问题：带 parent session、subagent kind/source 或 `(@... subagent)` 标题的内部会话会被隐藏，列表更接近 `opencode session list`。
- 新增 Quick Ask 临时答疑模式：`:OpencodeQuick` 打开轻量浮动窗口，复用当前模型配置但使用独立临时 session；关闭或取消后删除临时 session，并与主 Chat session/context 隔离。
- 修复对单个 Chat pane 执行 `:q` 后其它 message/input/status pane 残留的问题；现在同 tab 内三个 Chat pane 会作为一组同步关闭。
- 修复对单个 Quick Ask pane 执行 `:q` 后其它浮动 pane 残留的问题；现在关闭任意 Quick pane 会收起整组浮窗并清理临时 session。
- 修复 Visual 模式执行 Quick Ask context 追加后仍停留在 Visual 状态的问题；现在追加后会退出 Visual 模式。
- 调整 Quick Ask 输入体验：Insert 模式下 `q` 保持为普通输入字符，关闭 Quick 请使用 Normal `q`、`:q` 或 `:OpencodeQuickClose`。
- 调整 Quick Ask 全局快捷键：`keymaps.quick` 只注册 Normal 模式，避免 `<leader>Xq` 在 Insert 模式触发 which-key 或拦截逗号输入。
- 修复首次直接使用 Quick context 后立刻提问可能卡在 Thinking 的启动竞态：Quick context 会预热 opencode server，server 启动中再次请求会排队等待 ready。
- 改进 server ready 队列回调调度：启动完成后的等待回调统一切回主循环执行，避免在异步回调上下文继续创建 session/request。
- 新增 `OPENCODE_CHAT_DEBUG_LOG` / `OPENCODE_CHAT_DEBUG` 文件日志，用于定位 Quick Ask、server 启动、session/message 请求和 assistant 轮询卡住的具体阶段。
- 将 debug 日志暴露出的时序依赖改为显式 `stream_subscribe_delay_ms`：建立事件订阅后短暂延迟再发送 message，避免 Quick Ask 首次请求过快触发真实后端竞态。
