# 技术指南

## 架构概览

MVP 使用 Neovim 右侧普通 split panel 作为 Chat UI，后台启动 `opencode serve`，并通过本地 HTTP API 创建 session、发送 prompt、渲染回复。选择器 UI 优先使用 `nui.nvim`，缺失时退回内置 floating fallback。文件修改交给配置的 opencode agent 在后端完成。

```text
Neovim plugin
  ├─ right-side message/input/status windows 渲染 Chat UI
  ├─ 启动 opencode serve --port <port> --hostname <host>
  ├─ POST /session 创建 session，并传入当前 agent/model/variant
  ├─ 生成当前文件/选区引用和源码内容
  ├─ POST /session/:sessionID/message 发送 prompt / edit 请求
  ├─ GET /event/subscribe 尝试订阅 SSE 增量事件
  └─ POST /session/:sessionID/abort 取消当前请求
```

## 数据流

Normal 模式：

```text
用户按 <M-->
  -> 解析 project root
  -> toggle floating chat buffer
```

Visual 模式：

```text
用户选中文本并按 <M-->
  -> 解析当前 buffer 文件路径
  -> 计算相对 project root 的路径
  -> 读取 Visual 起止行并排序
  -> 生成 @relative/path#Lstart-Lend
  -> 加入下一次 prompt 的上下文队列
  -> 显示 Chat UI
```

推荐的上下文追加入口是用户配置的 `append_context`，例如 `<leader>Xe`：Normal 模式追加当前文件，Visual 模式追加当前选区，并保持焦点在代码 pane。旧的 Visual `append_selection` 入口继续可用，但会聚焦 Chat input。

## 模块职责

- `config.lua`：提供默认配置、provider/model/variant 白名单校验和当前选择状态。
- `root.lua`：根据 `.root`, `.git`, `.svn`, `.hg`, `.project`, `.ccls` 查找项目根目录。
- `server.lua`：管理 `opencode serve` job、端口、session 生命周期。
- `client.lua`：封装本地 HTTP 请求，重点是创建 session、发送 prompt 和订阅 SSE event。
- `ui.lua`：管理右侧 message/input/status windows、消息渲染和待提交上下文队列。
- `picker.lua`：提供 session/model/variant 选择浮窗，优先使用 `nui.menu`，支持键盘和鼠标选择，并跟随 Chat UI 生命周期关闭。
- `context.lua`：生成文件/选区引用，并读取对应源码内容。
- `commands.lua`：注册用户命令。
- `init.lua`：插件公开入口。

## 关键约束

- 不使用 terminal/TUI 作为协议层。
- 不引入 `vim-floaterm`；主 Chat UI 使用右侧普通 split window，选择器可使用 `nui.nvim`。
- 主 Chat UI 的宽度、高度和消息区高度需要通过 `ui.width`、`ui.height`、`ui.message_height` 配置。
- 不使用 `--continue` 复用历史 session；会话复用仅限同一个 Neovim 进程内的插件状态。
- Session 列表必须按当前 project/workspace 过滤：优先 `/project/:projectID/session`，fallback `/session` 时必须按 `projectID` 或 `directory` 过滤，不能直接展示全局 session。
- Session picker 需要支持 item-level 操作：`r` 重命名选中 session，`d` 删除选中 session 且删除前必须确认。
- Visual 追加上下文不能提交 prompt，只能加入下一次提问的上下文队列；队列中必须包含引用和源码内容。统一追加入口需要对相同引用去重，并在 `append_context` 下保持代码 pane 焦点。
- Context 区需要支持编号展示、按编号删除、清空全部；消息区 Context 行上 `d` 删除单项，`D` 清空全部。
- 选区行号必须保证 `Lstart <= Lend`。
- 文件修改由 opencode backend/agent 执行；插件负责发送带源码上下文的 edit 请求并展示 assistant 总结。
- Chat UI 必须支持消息区/输入区键盘切换、消息自动滚动到底部、请求取消和忙碌保护，避免多个请求并发卡在 `Thinking...`。
- 消息区必须保持 normal/read-only 体验；只有输入区可以自动进入 insert。隐藏 Chat UI 时必须同步关闭所有 picker。
- 当前 tab 若只剩 opencode-chat message/input/status 窗口，必须自动关闭 Chat 窗口；若还有其它 tab，直接关闭当前 tab；若是最后一个 tab，优先恢复最近的普通代码 buffer，只有找不到可恢复 buffer 时才创建普通空窗口保活。
- Toggle 行为兼具 reveal/focus：面板隐藏时打开，面板可见但失焦时聚焦输入区，焦点在 Chat 内时隐藏。
- Status bar 必须能显示 Idle/Thinking/Streaming/Error 等请求状态；SSE 不可用时必须保留非流式 fallback。
- 不默认注册全局快捷键；用户需要通过 `keymaps` 显式配置 toggle/session/model/variant 等入口。
- `model` 必须是 `provider/model`，且存在于 `providers` 白名单；variant 属于 provider 级能力，每个 model 只声明 `default_variant`。
- `agent`、`model`、`variant` 需要同时参与 session 创建和 message 请求：session 创建使用 `{ providerID, id, variant }`，message 请求使用 `{ providerID, modelID }` 并带顶层 `agent` / `variant`。
- 取消必须调用 opencode backend 的 abort API；本地停止 curl/轮询只能作为辅助清理，不能伪装成后端已取消。
- abort 成功后必须丢弃当前 session，下一次请求重新创建 session，避免复用已 abort 的会话继续得到 `MessageAbortedError`。

## 进程内状态

实现时可维护类似状态：

```lua
local state = {
  root = nil,
  port = nil,
  job_id = nil,
  session_id = nil,
  started = false,
  sessions = {},
}
```

该状态只在当前 Neovim 进程内有效，退出 Neovim 后不持久化。新建 session 只创建后端 session，不重启已运行的 `opencode serve`。
