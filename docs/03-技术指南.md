# 技术指南

## 架构概览

插件以 Neovim 原生 split Chat UI 连接 OpenCode V2 HTTP/SSE，当前验证基线为 v2.1.1，不兼容 V1。

```text
Neovim A / workspace-A                 Neovim B / workspace-B
  └─ 私有 OpenCode A                     └─ 私有 OpenCode B
      ├─ 主 session A                        ├─ 主 session B
      └─ Quick 临时 session                  └─ Quick 临时 session
```

每个 Neovim 首次聊天创建自己的 session，即使打开相同 workspace 也不自动共享。服务进程仍使用 OpenCode 持久化存储，进程隔离不等于数据库隔离。选择外部历史时先 fork 再继续对话；本进程拥有的 session 可直接恢复。

同一 Neovim 的 tab 镜像共享消息、草稿和上下文；提交时按 root 选择本进程的会话。Quick Ask 复用服务，使用独立临时 session 和上下文，不替换主会话。

## 私有服务生命周期

```text
安全随机密码 → opencode serve --stdio --hostname 127.0.0.1 --port 0
  → 子进程环境 OPENCODE_PASSWORD
  → stdout 分段解析 {"url":"http://127.0.0.1:实际端口"}
  → 配置 HTTP/SSE Basic 认证，保持 stdin 打开
  → OpencodeStop/退出 Neovim：关闭 stdin，等待退出，必要时 TERM/KILL
```

不使用 `--service`，不改变 `disabled=true`，不接管已有共享监听。默认使用动态端口；显式 `port` 仍可用，但多进程建议不设置固定端口。用户名为 `opencode`，密码仅保存在内存，经 curl stdin 配置传入，不出现在命令参数或日志中。

隐藏 Chat、切换 tab 或新建 session 不关闭服务 stdin。启动超时和提前退出会反馈到 UI，并附退出码与诊断信息。

## 请求数据流

1. 按 root 创建/选择 session，创建体显式包含 `location: { directory }`。
2. 通过 `/api/session/:id/agent`、`/model` 配置 agent/模型。模型引用为 `{ providerID, id, variant }`。
3. 订阅 `GET /api/event`；v2.1.1 的 `server.connected` 在 feed 订阅建立后发出，作为提交屏障。
4. POST `/api/session/:id/prompt`，发送 `{ text }`，保存 inbox ID。HTTP 200 仅表示接收输入，不代表生成完成。
5. SSE JSON 使用 `{ type, data }`，按 `data.sessionID` 过滤；`session.text.delta/ended` 构建正文，reasoning 不混入正文。
6. `session.execution.started/succeeded/failed/interrupted` 区分结果；成功后读取历史作为最终正文。step 结束不等于请求结束。
7. 重连不重发 prompt；查询 history 补齐丢失的 live-only delta。无法恢复时报错并尝试后端中断，不把本地 EOF 当作成功。

curl 负责 HTTP 状态、认证和 chunked 解码，`sse.lua` 仅解析 SSE。`: heartbeat` 注释帧也刷新存活检测。

## 取消与超时

prompt POST 尚在进行时先等输入接收结果，再 DELETE `/api/session/:id/inbox/:inboxID` 移除排队输入，最后 POST `/api/session/:id/interrupt?resume=false` 中断当前执行。失败显示 Error，不能仅关闭 curl 就显示 Cancelled。V2 中断保留本进程的会话。

响应超时同样清理 inbox 并尝试中断，但以超时错误结束。Quick Ask 关闭/取消后删除自己的临时 session；generation 标识防止迟到回调覆盖重开的窗口。

## 历史与工作目录

- GET `/api/session?directory=...` 处理分页，并按规范化的 `location.directory` 二次过滤；隐藏子会话和 subagent。
- 历史响应为 `{ data, cursor }`；user 读取 `text`，assistant 仅提取 `content` 的 text，不沿用 V1 `{ info, parts }`。
- 历史先验证位置，再恢复本进程 session 或 fork 外部 session；读取成功后才切换当前 session。
- 默认模型为 `deepseek/deepseek-flash`，默认不传 agent，遵循后端配置；无效显式模型/agent 报错，不静默替换。

## 模块职责

| 模块 | 职责 |
|---|---|
| `config.lua` / `root.lua` | 配置白名单、当前模型、项目 root |
| `server.lua` | 私有 job、stdin 租约、session 所有权、目录映射和历史操作 |
| `client.lua` | V2 HTTP 合约、认证、分页与消息投影 |
| `sse.lua` / `chat.lua` | SSE 传输及单请求接收、执行、恢复、取消 |
| `ui.lua` / `quick_ui.lua` | 主 split/tab 镜像、临时浮窗、消息和上下文 |
| `quick.lua` | 临时会话请求与清理 |
| `picker.lua` / `context.lua` | 选择器与文件/选区引用 |
| `commands.lua` / `init.lua` | 命令、公开 API 与 UI 调度 |

## 当前限制

权限审批和 form 回答 UI 尚未实现；`permission.asked` / `form.created` 显示等待原因，可取消请求，不自动放行权限。provider/model/variant 白名单仍由用户维护。
