# 技术指南

## 架构概览

MVP 使用 Neovim 原生 floating buffer 作为 Chat UI，后台启动 `opencode serve`，并通过本地 HTTP API 创建 session、发送 prompt、渲染回复。

```text
Neovim plugin
  ├─ native floating buffer 渲染 Chat UI
  ├─ 启动 opencode serve --port <port> --hostname <host>
  ├─ POST /api/session 创建 session
  ├─ 生成当前文件/选区引用
  └─ POST /api/session/:sessionID/prompt 发送 prompt
```

## 数据流

Normal 模式：

```text
用户按 <M-->
  -> 解析 project root
  -> toggle floating chat buffer
```

Visual 模式：

```text
用户选中文本并按 <M-->
  -> 解析当前 buffer 文件路径
  -> 计算相对 project root 的路径
  -> 读取 Visual 起止行并排序
  -> 生成 @relative/path#Lstart-Lend
  -> 加入下一次 prompt 的上下文队列
  -> 显示 Chat UI
```

## 模块职责

- `config.lua`：提供默认配置并合并用户配置。
- `root.lua`：根据 `.root`, `.git`, `.svn`, `.hg`, `.project`, `.ccls` 查找项目根目录。
- `server.lua`：管理 `opencode serve` job、端口、session 生命周期。
- `client.lua`：封装本地 HTTP 请求，重点是创建 session 和发送 prompt。
- `ui.lua`：管理 floating chat buffer、消息渲染和待提交上下文队列。
- `context.lua`：生成文件引用和选区引用。
- `commands.lua`：注册用户命令。
- `init.lua`：插件公开入口。

## 关键约束

- 不使用 terminal/TUI 作为协议层。
- 不引入 `vim-floaterm`；MVP 只使用 Neovim 原生 buffer/floating window API。
- 不使用 `--continue` 复用历史 session；会话复用仅限同一个 Neovim 进程内的插件状态。
- Visual 追加上下文不能提交 prompt，只能加入下一次提问的上下文队列。
- 选区行号必须保证 `Lstart <= Lend`。

## 进程内状态

实现时可维护类似状态：

```lua
local state = {
  root = nil,
  port = nil,
  job_id = nil,
  session_id = nil,
  started = false,
}
```

该状态只在当前 Neovim 进程内有效，退出 Neovim 后不持久化。
