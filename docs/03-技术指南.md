# 技术指南

## 架构概览

MVP 使用 opencode TUI 作为界面，Neovim 只负责承载终端窗口、管理进程生命周期，并通过本地 HTTP bridge 追加上下文。

```text
Neovim plugin
  ├─ native floating terminal 承载 opencode TUI
  ├─ 启动 opencode --port <port>
  ├─ 生成当前文件/选区引用
  └─ POST /tui/append-prompt 追加文本
```

## 数据流

Normal 模式：

```text
用户按 <M-->
  -> 解析 project root
  -> 确保 opencode TUI 已启动
  -> toggle floating terminal
  -> 可追加 @relative/path
```

Visual 模式：

```text
用户选中文本并按 <M-->
  -> 解析当前 buffer 文件路径
  -> 计算相对 project root 的路径
  -> 读取 Visual 起止行并排序
  -> 生成 @relative/path#Lstart-Lend
  -> POST /tui/append-prompt
  -> 聚焦或显示 opencode TUI
```

## 模块职责

- `config.lua`：提供默认配置并合并用户配置。
- `root.lua`：根据 `.root`, `.git`, `.svn`, `.hg`, `.project`, `.ccls` 查找项目根目录。
- `terminal.lua`：管理 floating window、terminal buffer、opencode job 和 toggle 语义。
- `client.lua`：封装本地 HTTP 请求，重点是 `/tui/append-prompt`。
- `context.lua`：生成文件引用和选区引用。
- `commands.lua`：注册用户命令。
- `init.lua`：插件公开入口。

## 关键约束

- 不使用 `chansend()` 给 opencode TUI 输入框注入文本。
- 不引入 `vim-floaterm`；MVP 只使用 Neovim 原生 terminal/floating window API。
- 不使用 `--continue` 复用历史 session；会话复用仅限同一个 Neovim 进程内的插件状态。
- Visual 追加上下文不能提交 prompt。
- 选区行号必须保证 `Lstart <= Lend`。

## 进程内状态

实现时可维护类似状态：

```lua
local state = {
  root = nil,
  port = nil,
  job_id = nil,
  win_id = nil,
  buf_id = nil,
  started = false,
}
```

该状态只在当前 Neovim 进程内有效，退出 Neovim 后不持久化。
