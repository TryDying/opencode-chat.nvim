# 项目指南

## 项目定位

`opencode-chat.nvim` 是一个面向 Neovim 的轻量 opencode 集成插件。第一版目标是用最小功能替代 `CopilotChat.nvim` 的常用问答入口：在编辑器中打开原生 Chat UI，把当前文件或选区作为上下文，并通过 opencode headless/server API 获取回复。

## MVP 范围

第一阶段实现基于 `opencode serve` 的最小原生 Chat UI：

- Normal 模式通过 `<M-->` 打开或隐藏 Chat UI。
- Visual 模式通过 `<M-->` 将当前选区引用加入下一次提问上下文。
- `:OpencodeAsk` 发送问题并在 Chat UI 中渲染回复。
- `:OpencodeQuick` 打开轻量临时答疑浮窗，用于与当前主 session 无关的旁支问题。
- 同一个 Neovim 进程内复用同一个 opencode server，并支持选择/新建 session。
- 重启 Neovim 后创建新的 opencode session。
- 追加上下文后不自动提交，等待用户继续提问。

## 使用场景

- 连续问答：使用 `:OpencodeToggle` 打开右侧 Chat UI，基于当前 session 持续对话，可选择、重命名或删除历史 session。
- 快速答疑：使用 `:OpencodeQuick` 打开浮动小窗，复用同一套 agent/model/variant 配置，可在窗口内多轮追问；关闭或取消后会删除本次临时 session，不进入主 Chat 历史。

## 非目标

第一版暂不实现：

- 文件树、prompt templates、agent/mode UI 切换。
- `vim-floaterm` 后端。

## 交互方式

插件启动：

```sh
opencode serve --port <port> --hostname 127.0.0.1
```

然后通过本地 HTTP API 创建 session 并发送 prompt：

```http
POST /session
POST /session/:sessionID/message
```

上下文引用和源码内容会拼入下一次 prompt 中，assistant 回复会渲染到插件自己的 UI。文件修改由配置的 opencode agent 在后端完成。

## 文件引用格式

当前文件引用：

```text
@relative/path/to/file.lua
```

选区引用：

```text
@relative/path/to/file.lua#L10-L30
```

选区行号始终按升序输出，即使用户反向选择文本。
