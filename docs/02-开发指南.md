# 开发指南

## 当前状态

仓库已实现第一版 MVP 插件代码，并包含一个不读取全局 Neovim 配置的自闭环测试脚本。当前尚未加入 lint/format 配置或包管理脚本。

## 本地开发准备

需要的基础环境：

- Neovim，版本以后续实现实际使用的 API 为准。
- opencode CLI，需支持 `opencode serve --port <port> --hostname <host>`、`POST /session` 和 `POST /session/:sessionID/message`。
- `curl`，MVP 初期可用于验证本地 HTTP bridge。
- 推荐安装 `nui.nvim`，用于更稳定的选择器 UI；未安装时测试仍可使用内置浮窗 fallback。

## 使用方式

用户侧配置可以类似：

```lua
require("opencode_chat").setup()

vim.keymap.set("n", "<M-->", function()
  require("opencode_chat").toggle()
end, { desc = "Toggle opencode" })

vim.keymap.set("v", "<M-->", function()
  require("opencode_chat").append_selection()
end, { desc = "Append selection to opencode" })
```

测试默认配置使用：

```lua
{
  agent = "quick",
  model = "deepseek/deepseek-v4-flash",
  providers = {
    deepseek = {
      variants = { "low", "medium", "high", "max" },
      models = {
        { id = "deepseek-v4-flash", default_variant = "low" },
        { id = "deepseek-v4-pro", default_variant = "high" },
      },
    },
    ["opencode-go"] = {
      variants = { "low", "medium", "high" },
      models = {
        { id = "qwen3-coder", default_variant = "medium" },
      },
    },
  },
  keymaps = {
    toggle = "<M-->",
    append_context = "<leader>Xe",
    append_selection = "<M-->",
    sessions = "<leader>Xl",
    new_session = "<leader>Xn",
    models = "<leader>Xm",
    variants = "<leader>Xt",
  },
  ui = {
    width = 0.4,
    height = 1.0,
    message_height = nil,
    input_height = 5,
  },
}
```

这些配置会限制可选模型和 provider 对应的 variant；provider ID 含 `-` 时可使用 `["opencode-go"] = { ... }`，也可使用 array-style `{ id = "opencode-go", ... }`。创建 session 和发送 message 都会携带当前 `agent/model/variant`，但两处 model schema 不同。插件默认不绑定全局快捷键，`keymaps` 中的条目才会被注册。`ui.width` 控制右侧面板宽度比例，`ui.height` 控制面板高度比例，`ui.message_height` 可用于固定消息区高度。

## 开发态启动

开发态启动当前仓库插件：

```sh
./scripts/dev-sandbox
```

该脚本会创建 `/tmp/opencode-chat.nvim-sandbox`，打开其中的临时代码文件，并通过 `scripts/dev-nvim` 强制使用 `VIM_PROFILE=basic`。开发态脚本会显式注入推荐测试快捷键（`<M-->`、`<leader>Xe/Xl/Xn/Xm/Xt`），其中 toggle 会注册 Normal/Insert `<M-->`，Insert 模式下先退出 insert 再执行 toggle；插件默认配置仍不注册全局快捷键。它不会修改全局 Neovim 配置，也不会把仓库内受 Git 管理的文件当作测试目标。

## 测试命令

在插件项目目录中运行：

```sh
VIM_PROFILE=basic nvim --headless -l tests/run.lua
```

该命令会加载当前仓库的插件入口，使用 `tests/fixtures/opencode` 模拟 `opencode serve` 的 `/app`、`/session`、`/project/:projectID/session`、`/session/:sessionID/message`、`/session/:sessionID/abort` 和 session 列表，不会修改全局 Neovim 配置。

## 验证方式

自动化测试覆盖插件加载、root 检测、引用生成、上下文代码读取、headless prompt 闭环、toggle 复用同一 job/session、session/model/variant 选择、后端 agent 修改文件。真实 opencode 的最小手动验证包括：

1. 在一个项目内打开 Neovim。
2. 执行 `:OpencodeToggle`，确认右侧 40% Chat panel 打开；焦点离开 Chat 后再次执行应回到输入区，焦点在 Chat 内时才隐藏。
3. 在下方输入区输入问题，按 `<C-s>`，确认能创建 session、发送 prompt 并渲染回复。
4. 用 `<Tab>` 在消息区和输入区之间切换，确认消息区可键盘聚焦。
5. 连续提问时确认繁忙提示出现；用 `<C-c>` 或 `:OpencodeCancel` 可通过 opencode abort API 取消当前请求。
6. 重复 toggle，确认只是隐藏/显示 UI，不创建新 server/session。
7. 用 `<leader>Xn` 新建 session，确认不重启 server；用 `<leader>Xl` 只看到当前 project 的 session，并可切回历史 session；在 session picker 内按 `r` 重命名、按 `d` 并确认后删除。
8. 用 `<leader>Xm` 选择模型、`<leader>Xt` 选择 variant，确认后续请求 payload 生效。
9. 发送较慢请求时观察 status bar 显示 Thinking/Streaming；如果真实 opencode 支持 SSE，应能看到 assistant 回复增量刷新。
10. Normal `<leader>Xe` 追加当前文件，Visual `<leader>Xe` 追加选区，确认 Chat UI 的 Context 区编号展示且代码 pane 仍保持焦点；重复追加同一项不会产生重复 context。
11. 在消息区 Context 行按 `d` 删除单项，按 `D` 清空全部；也可用 `:OpencodeContextRemove {index}` / `:OpencodeContextClear`。
12. 再在输入区提问，确认上下文引用和代码内容被拼入本次 prompt。
13. 反向 Visual 选择后确认输出行号仍为升序。
14. 执行 `:OpencodeEdit 修改说明`，确认 opencode backend 修改 sandbox 文件，并在 Chat UI 中显示 assistant 总结。

后续如果加入 `luacheck`、`stylua` 或更多测试框架，应在本文件补充准确命令。
