# 开发指南

## 当前状态

仓库已实现第一版 MVP 插件代码，并包含一个不读取全局 Neovim 配置的自闭环测试脚本。当前尚未加入 lint/format 配置或包管理脚本。

## 本地开发准备

需要的基础环境：

- Neovim，版本以后续实现实际使用的 API 为准。
- opencode CLI，需支持 `opencode serve --port <port> --hostname <host>`、`POST /api/session` 和 `POST /api/session/:sessionID/prompt`。
- `curl`，MVP 初期可用于验证本地 HTTP bridge。

## 使用方式

用户侧配置可以类似：

```lua
require("opencode_chat").setup()

vim.keymap.set("n", "<M-->", function()
  require("opencode_chat").toggle()
end, { desc = "Toggle opencode" })

vim.keymap.set("v", "<M-->", function()
  require("opencode_chat").append_selection()
end, { desc = "Append selection to opencode" })
```

## 开发态启动

开发态启动当前仓库插件：

```sh
./scripts/dev-nvim README.md
```

该脚本使用 `nvim --clean -u NONE`，只把当前仓库加入 runtimepath，并加载 `plugin/opencode_chat.lua`。

## 测试命令

在插件项目目录中运行：

```sh
nvim --clean -u NONE --headless -l tests/run.lua
```

该命令会加载当前仓库的插件入口，使用 `tests/fixtures/opencode` 模拟 `opencode serve` 的 `/app`、`/api/session` 和 `/api/session/:sessionID/prompt`，不会读取或修改全局 Neovim 配置。

## 验证方式

自动化测试覆盖插件加载、root 检测、引用生成、headless prompt 闭环，以及 toggle 复用同一 job/session 的行为。真实 opencode 的最小手动验证包括：

1. 在一个项目内打开 Neovim。
2. 执行 `:OpencodeToggle`，确认原生 Chat UI 打开。
3. 执行 `:OpencodeAsk hello`，确认能创建 session、发送 prompt 并渲染回复。
4. 重复 toggle，确认只是隐藏/显示 UI，不创建新 server/session。
5. Visual 选择几行后触发追加，确认 Chat UI 的 Context 区出现 `@relative/path#Lx-Ly`。
6. 再执行 `:OpencodeAsk 你的问题`，确认上下文被拼入本次 prompt。
7. 反向 Visual 选择后确认输出行号仍为升序。

后续如果加入 `luacheck`、`stylua` 或更多测试框架，应在本文件补充准确命令。
