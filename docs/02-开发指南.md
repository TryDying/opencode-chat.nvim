# 开发指南

## 当前状态

仓库已实现第一版 MVP 插件代码，并包含一个不读取全局 Neovim 配置的自闭环测试脚本。当前尚未加入 lint/format 配置或包管理脚本。

## 本地开发准备

需要的基础环境：

- Neovim，版本以后续实现实际使用的 API 为准。
- opencode CLI，需支持 `opencode serve --port <port> --hostname <host>`、`POST /session` 和 `POST /session/:sessionID/message`。
- `curl`，MVP 初期可用于验证本地 HTTP bridge。

## 使用方式

用户侧配置可以类似：

```lua
require("opencode_chat").setup()

vim.keymap.set("n", "<M-->", function()
  require("opencode_chat").toggle()
end, { desc = "Toggle opencode" })

vim.keymap.set("v", "<M-->", function()
  require("opencode_chat").append_selection()
end, { desc = "Append selection to opencode" })
```

测试默认配置使用：

```lua
{
  agent = "quick",
  model = "deepseek/deepseek-v4-flash",
  variant = "low",
}
```

这些配置在创建 session 时发送给 opencode；发送消息时只提交 prompt parts，避免把会话配置混入每条消息。

## 开发态启动

开发态启动当前仓库插件：

```sh
./scripts/dev-sandbox
```

该脚本会创建 `/tmp/opencode-chat.nvim-sandbox`，打开其中的临时代码文件，并通过 `scripts/dev-nvim` 强制使用 `VIM_PROFILE=basic`。它不会修改全局 Neovim 配置，也不会把仓库内受 Git 管理的文件当作测试目标。

## 测试命令

在插件项目目录中运行：

```sh
VIM_PROFILE=basic nvim --headless -l tests/run.lua
```

该命令会加载当前仓库的插件入口，使用 `tests/fixtures/opencode` 模拟 `opencode serve` 的 `/app`、`/session`、`/session/:sessionID/message` 和 `/session/:sessionID/abort`，不会修改全局 Neovim 配置。

## 验证方式

自动化测试覆盖插件加载、root 检测、引用生成、上下文代码读取、headless prompt 闭环、toggle 复用同一 job/session、后端 agent 修改文件。真实 opencode 的最小手动验证包括：

1. 在一个项目内打开 Neovim。
2. 执行 `:OpencodeToggle`，确认原生 Chat UI 打开。
3. 在下方输入区输入问题，按 `<C-s>`，确认能创建 session、发送 prompt 并渲染回复。
4. 用 `<Tab>` 在消息区和输入区之间切换，确认消息区可键盘聚焦。
5. 连续提问时确认繁忙提示出现；用 `<C-c>` 或 `:OpencodeCancel` 可通过 opencode abort API 取消当前请求。
6. 重复 toggle，确认只是隐藏/显示 UI，不创建新 server/session。
7. Visual 选择几行后触发追加，确认 Chat UI 的 Context 区出现 `@relative/path#Lx-Ly`。
8. 再在输入区提问，确认上下文引用和代码内容被拼入本次 prompt。
9. 反向 Visual 选择后确认输出行号仍为升序。
10. 执行 `:OpencodeEdit 修改说明`，确认 opencode backend 修改 sandbox 文件，并在 Chat UI 中显示 assistant 总结。

后续如果加入 `luacheck`、`stylua` 或更多测试框架，应在本文件补充准确命令。
